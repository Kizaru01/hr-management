# Employee mobile app

Existing Expo SDK 57 / React Native 0.86 / Expo Router workspace. Native Android and iOS only for authenticated use: credentials require Expo SecureStore. The web target intentionally has no insecure browser-storage fallback.

## Local setup (PowerShell, repository root)

1. Install Node 22.13+ and pnpm 10.22.0. Run `pnpm install`.
2. Build shared packages in order:
   ```powershell
   pnpm --filter @hr-management/constants build
   pnpm --filter @hr-management/validation build
   ```
3. Use the existing backend environment and database setup. In one terminal run `pnpm --filter api dev`. Nest listens on port 4000 unless its PORT setting overrides that. Do not copy the backend .env into mobile.
4. Create the mobile environment file:
   ```powershell
   Copy-Item apps/mobile/.env.example apps/mobile/.env.local
   ```
   Set EXPO_PUBLIC_API_URL in that file to the Nest base URL (no /api suffix):
   - Android Studio emulator: `http://10.0.2.2:4000`.
   - Physical Android/iPhone: `http://<computer-LAN-IPv4>:4000`. Find the address with `ipconfig`. Both devices must be on the same reachable Wi-Fi/LAN; allow the API port and Expo dev server port through the local firewall for the private network.
   - iOS simulator on a Mac running Nest: `http://localhost:4000`.
   - localhost on a physical device means the device itself, not your development computer. A tunnel for Metro does not automatically tunnel Nest.
   - HTTPS is required by the app in release builds. For native builds where OS transport policy blocks LAN HTTP, use a trusted HTTPS development endpoint; the app does not weaken release transport security.
5. Start Metro with `pnpm --filter mobile start --clear`. If Windows cannot resolve the Expo command shim, use:
   ```powershell
   Set-Location apps/mobile
   node node_modules/expo/bin/cli start --clear
   ```
6. Android first: start an Android Studio emulator with Google Play, then press `a` in Metro. For a physical phone, install an Expo Go version supporting SDK 57 and scan the QR code. Use a development build if your Expo Go version does not support this SDK. SecureStore is a native module; rebuild an existing development client after adding it. No native project is generated by this milestone.
7. Sign in with an existing activated employee or manager account linked to an employee record. Use the existing web activation flow if needed. Do not use an HR/admin account; those roles are intentionally rejected by this employee app.

For iOS, use SDK-compatible Expo Go on a physical device, or an iOS simulator on macOS. Windows cannot run the iOS simulator. Native apps call Nest directly; the existing WEB_URL CORS setting is for browser clients, not native requests. Do not broaden CORS just to preview mobile in a browser.

## Screens and contracts

All calls use the existing `{ success, message, data }` convention and send bearer authorization directly to Nest. The mobile client uses a 15-second timeout, cancellation, structured HTTP/network errors, and runtime parsers for consumed fields. No Next.js BFF calls.

| Endpoint | Usage |
| --- | --- |
| POST /auth/login | Shared loginSchema; flat data.accessToken/id/email/role/lastLoginAt |
| GET /auth/me | Validate saved/new token and current account role/status |
| GET /employees/me | Select work identity, employee number, work email, department, position, branch, hire date and employment fields; discard other returned fields |
| GET /attendance/me/status | Read-only status union: holiday/name, rest_day, scheduled, absent, on_leave/leave, or check-in/out timestamps and late/undertime minutes |
| GET /announcements | Existing employee audience/publication/expiry filtering; display first three in server order |
| GET /notifications/unread-count | Existing aggregate unread count; zero only after a successful response |

Home and Profile are the only tabs. Profile is the only shortcut. No attendance mutation, leave submission, notification mutation, team management, or placeholder destinations are included.

The self-service attendance response does not contain assigned shift details. The shift controller only authorizes admin/hr/manager, so mobile does not call it for personal shift lookup or change its permissions. Attendance calculations stay on the backend. Business timestamps use Asia/Manila; date-only values retain their calendar date. GET /leave/me was inspected but is not fetched just to derive a count; the supported notification aggregate provides the home summary instead.

Managers are explicitly supported by existing personal attendance routes and the web employee layout. They receive personal data only here. Shared domain UserRole omits manager, and domain Employee uses Date objects; these are not reused as wire types. Shared login validation and USER_ROLES constants are reused.

## Authentication and privacy

- Only the access token is stored, in Expo SecureStore with WHEN_UNLOCKED_THIS_DEVICE_ONLY. Passwords and employee records are never persisted or logged. No AsyncStorage, localStorage, cookies, or token logging.
- Launch restoration checks GET /auth/me before private routes mount. Returning to the foreground revalidates the session. Protected Router groups remove access to private navigation when signed out.
- Nest issues 15-minute access tokens. There is no refresh-token or Nest logout endpoint. Any authenticated 401 clears the token and returns to login; a feature-level 403 remains a permission error. No invented refresh flow.
- Network/server failures preserve the saved token and offer retry. SecureStore errors lock access and offer retry; failure to delete is never reported as successful sign-out.
- Sign-out deletes local credentials; it cannot revoke an already-issued JWT server-side. No server revocation endpoint is implemented by this milestone.
- EXPO_PUBLIC_API_URL is public configuration bundled into the app. Never add database URLs, JWT signing secrets, email-service keys, Blob tokens, or credentials to EXPO_PUBLIC variables.

## Verification commands

```powershell
pnpm --filter mobile typecheck
pnpm --filter mobile lint
Set-Location apps/mobile
node node_modules/expo/bin/cli install --check
pnpm dlx expo-doctor
node node_modules/expo/bin/cli export --platform android --output-dir dist/android
node node_modules/expo/bin/cli export --platform ios --output-dir dist/ios
```

Native acceptance: sign in; inspect Home and Profile; force-close/relaunch to restore; disable networking and retry without losing the token; wait beyond the 15-minute JWT lifetime and refresh/reopen to verify return to login; sign out and relaunch; verify manager personal access and admin/hr rejection. Check both OS themes, keyboard, large text, and Android back behavior. Do not create employee records or modify attendance for this read-only milestone.
